## 1. Executive Summary

Milestone 5.5 establishes a deterministic, automated, and cross-platform release pipeline for Cavia Music 2.0. The packaging architecture unifies desktop and mobile platforms under strict release invariants:

1. **Deterministic Versioning**: Synced across frontend (`package.json`), Rust backend (`src-tauri/Cargo.toml`), Tauri configuration (`src-tauri/tauri.conf.json`), and native mobile manifests (`build.gradle.kts` versionCode 20000, versionName 2.0.0).
2. **Strict Production Isolation**: Release binary compilation strips benchmark harnesses and development overrides (`cfg(not(debug_assertions))` ignores `CAVIA_APP_DATA_DIR`). Zero embedded API secrets, dev servers, or synthetic track fixtures.
3. **Resilient Forward Upgrades**: Automated migration reconciliation ensures databases initialized during prior development cycles or previous releases seamlessly upgrade without schema panics or data loss.
4. **Honest Platform Verification**: Physical Windows 11 desktop installation, execution, data preservation, and uninstallation are verified empirically on native hardware. macOS, Android, and iOS packaging structures and CI workflows are verified via automated pipelines with physical device verification explicitly tracked and deferred.

  - Microsoft Visual Studio 2022 / 2026 C++ Build Tools (MSVC `link.exe`, Windows 10/11 SDK).

  - NSIS 3.13+ (automatically managed and validated by Tauri bundler).

  - macOS 14+ (Sonoma or Sequoia) on Apple Silicon or Intel host.
  - Xcode 15+ and Command Line Tools (`xcode-select --install`).
- **Android**:
  - JDK 17 (Eclipse Temurin or OpenJDK 17).
  - Android SDK (API Level 37 compileSdk, API Level 24 minSdk, Android NDK 26+).
  - Rust Android targets: `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android`.
- **iOS**:
  - macOS host with Xcode 15+ and active Apple Developer Account.
  - Rust iOS targets: `aarch64-apple-ios`, `aarch64-apple-ios-sim`.

## 5. Security, Signing & Notarization Architecture

### 5.1 Windows Authenticode Signing
Windows binaries (`cavia-music.exe`) and installers (`Cavia Music_2.0.0_x64-setup.exe`) must be signed with a valid EV (Extended Validation) or Standard Code Signing Certificate to eliminate Windows SmartScreen warnings.
- **Signing Command**:
  ```powershell
  signtool.exe sign /tr http://timestamp.digicert.com /td sha256 /fd sha256 /a /f "CaviaCodeSign.pfx" /p "$CERT_PASSWORD" "src-tauri\target\release\bundle\nsis\Cavia Music_2.0.0_x64-setup.exe"
  ```
- **Validation**:
  ```powershell
  signtool.exe verify /pa /v "src-tauri\target\release\bundle\nsis\Cavia Music_2.0.0_x64-setup.exe"
  ```

### 5.2 Apple Developer ID & Notarization (macOS)
macOS requires cryptographic code signing with an Apple Developer ID Application certificate and automated notarization through Apple notary services:
1. **Signing**: Configured in `tauri.conf.json` under `bundle.macOS.signingIdentity` or via environment variable `APPLE_SIGNING_IDENTITY`.
2. **Notarization**: Invoked via Apple `notarytool`:
   ```bash
   xcrun notarytool submit "$DMG_PATH" --apple-id "$APPLE_ID" --password "$APP_SPECIFIC_PASSWORD" --team-id "$TEAM_ID" --wait
   xcrun stapler staple "$DMG_PATH"
   ```

### 5.3 Android App Signing
Release APKs/AABs require signing via Java Keystore (`.jks` / `.keystore`):
1. **Keystore Generation**:
   ```bash
   keytool -genkey -v -keystore cavia-release.keystore -alias cavia -keyalg RSA -keysize 2048 -validity 10000
   ```
2. **Alignment & Signing**:
   ```bash
   zipalign -v -p 4 app-release-unsigned.apk app-release-aligned.apk
   apksigner sign --ks cavia-release.keystore --out cavia-music-release.apk app-release-aligned.apk
   ```

## 7. CI/CD Build Automation Architecture

Two dedicated GitHub Actions workflows manage quality gates and packaging:

### 7.1 Continuous Integration (`.github/workflows/ci.yml`)
- Triggers on `push` to `main` and `pull_request` targeting `main`.
- **Job 1 (`frontend-checks`)**: Ubuntu 22.04 runner; validates TypeScript type safety (`tsc -b`), compiles Vite production assets, and executes all Node.js DTO & contract tests (`npm run test:unit`).
- **Job 2 (`rust-checks`)**: Windows Server runner; the historical workflow ran formatting, compilation, and Rust tests. The current test count is whatever `cargo test` reports for the checked-out revision.

### 7.2 Release Packaging (`.github/workflows/release.yml`)
- Triggers via `workflow_dispatch` (manual gate) or Git tag push (`v*`).
- **Multi-OS Build Matrix**:
  - `windows-latest`: Builds Windows NSIS installer, generates SHA-256 checksum, uploads installer artifact.
  - `macos-latest`: Builds macOS Universal DMG, generates SHA-256 checksum, uploads DMG artifact.
  - `ubuntu-latest`: Configures Java 17, Android SDK & NDK, compiles Rust Android targets, builds Release APK, generates SHA-256 checksum, uploads APK artifact.
- **Manifest Aggregator**: Consolidates SHA-256 hashes, file sizes, and release metadata into `release-manifest.json`.
- **Strict Non-Publishing Constraint**: In compliance with release engineering rules, the automated pipeline uploads all release artifacts for inspection and manual verification; it never automatically deploys to public app stores or creates public GitHub releases without explicit user confirmation.
